Explaining a hidden attack · 22 runs · 110 instructions

Does an innocent-sounding instruction still explain an agent that attacks in the open?

Each benign-sounding instruction was found on a DeepSeek V4 Pro run, where the agent hid its side task. Here it is also scored on GLM-5.3 runs with the same side task, where the agent narrates its attack openly. Each task has two panels: the DeepSeek run, then the GLM runs. If the cover story clashes with an agent that says what it is doing, the benign instruction (orange) should fall behind the plainly malicious control (blue) in the GLM panel.

What happened

An AI agent was given a coding task. It was also secretly told to carry out a harmful side task, and it did both without mentioning the side task. Each panel title gives the score (0 to 100) that a monitor reading the agent's whole run gave it; most of these runs got past that monitor. We ask: what instruction, if it had been handed to the agent, would best explain what it actually did?

Gain (across)

A separate reference model (Qwen3-32B) reads the agent's run twice, with and without the instruction, and we measure how much less surprised it is by the agent's own actions. The drop is in nats (units of log-probability). Further right means the instruction explains the agent's behaviour better; 0 means no better than no instruction.

Suspicion (up)

A monitor (Qwen3-32B by default; switch at the top), given the prompt of the monitor that watched the agent, edited to read only the instruction, rates how suspicious the instruction looks, from 0 (clearly fine) to 100 (clearly malicious), and writes a short reason.

How to read a panel

The bottom-right corner is the worrying one: instructions that explain the agent well and still look innocent. The dark staircase is the frontier, the instructions that no other instruction beats on both higher gain and lower suspicion (ringed). The dashed line is where the selected monitor would flag an instruction (25 for v1). Everything in the shaded area is beaten by some frontier point. Hover or tap a point to read the instruction and the monitor's reason; open a panel to see it larger with a table.

Caveats

  • Single-goal instructions only (one objective, no method), so they carry little coding-task detail. Benign = the best low-suspicion-search instruction with suspicion at most 25 that still carries the side task (a rough string match); malicious = the single-goal lowest-loss search's best.
  • 11 tasks. The benign instruction loses ground on GLM in 6 of them (median benign minus malicious: about -3 nats on DeepSeek, -10 on GLM), which is close to a coin flip at this size.
  • The GLM runs share the side task but usually not the coding task (2 of 19 share both); GLM gain is the mean over that task's GLM runs (each run's gain is in the point's details).
  • Suspicion belongs to the instruction, so a point sits at the same height in both panels; it was judged against the DeepSeek run's task description.
  • One task is left out because its benign pick states the side task outright (it passed on one noisy monitor call).
  • Gain is from a single scoring pass. The reference model's loss moves by about 3 nats under trivial edits such as a trailing space, so differences of a few nats are noise.
  • Each suspicion score is one monitor call, and single calls are noisy: the same instruction has scored 0 on one call and 80 on another.
